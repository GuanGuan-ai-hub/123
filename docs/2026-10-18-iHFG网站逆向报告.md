## 1. 执行摘要

iHFG 是澳大利亚 TAHPI 公司运营的国际医疗设施设计指南网站,核心资产是 **607 个标准房间组件(Standard Components)**、**63 个功能规划单元(FPU)**、**10 个指南分册(Guidelines Parts)**,以"免费在线浏览 + 付费下载 Revit 文件 + SaaS(HFBS)在线编辑"三级变现模式运营。

**技术本质:典型的 ASP.NET MVC 5 服务端渲染站,无前后端分离、无公开 API、无 SPA**。所有数据一次性输出为 HTML,客户端仅用 jQuery + DataTables 做分页搜索。这对复刻极其有利——架构简单、数据全在 HTML 里、无反爬 API 加密。

## 4. 核心数据模型(逆向还原)

### 4.1 Standard Component(核心实体)

**列表字段**(607 条已提取至 `2026-10-18-standard-components.json`):

```json
{ "slug": "1-Bed-Room-Bariatric-20m2", "name": "1 Bed Room - Bariatric, 20m2", "code": "1BR-BA-20-I" }
```

**编码规则**:`{床位数/类型缩写}-{变体}-{面积?}-I`,后缀 `-I` 表示 International 版。高频前缀:1BR(29) / OR(23) / OFF(16) / ENS(15) / MEET(13) / STGN(11)……

**详情页(RDS)字段结构**(以 1BR-BA-20 为样本):

```
1. 头部区:名称、Room Code、Net Room Area Briefed(20)、
   Hours of Operation(24 Hours)、Occupancy(1 patient; 1-2 staff; 1-2 visitors)、
   Description / Special Requirements、Amendment(修订历史:日期+说明,多条)
2. 建筑装修表(Architectural Finishes)7列:
   ID | Fabric | Material | Finish | Specification | Selection | Remarks
   行示例:3092 | Wall protection | MDF | Laminate | Bed protection wall panel | | behind bed
   (覆盖墙/地/顶/门/窗/踢脚/护角等建筑元素)
3. 设备家具表(Equipment & Fittings)6列:
   ID | Description | Category | Group | Qty | Selection/Remarks
   Category 取值:Furniture/Fitting、Metalwork、MEQ-General(医疗设备)、MEQ-Furniture 等
   每个物品有全局 ID(如 8309=Oxygen flowmeter),说明有统一设备主数据库
4. 文件区:
   - HFBS Edit Briefing(外链)
   - RLS PDF:Free + View 按钮
   - Revit RLS:$64.99 + Add to Cart 按钮
```

### 4.2 Guideline / FPU

- 指南分册页三段式:Complete Part(整册PDF)→ Chapters(章节PDF列表)→ Functional Planning Units(该册涵盖的 FPU PDF 列表)
- FPU PDF slug 规则:`iHFG_part_b_{unit_name}`,如 `iHFG_part_b_emergency_unit`、`iHFG_part_b_birthing_unit`(63 个已见于 FPUs.html)

### 4.3 文件实体

- RLS PDF:真实 PDF(样本 749KB / 3 页),`Content-Type: application/pdf` 浏览器内联,无防盗链(带 UA 即可直下)
- Revit 文件:付费墙后,未采样

## 12. 交互↔业务一致性实证(2026-10-19 第二轮)

### 12.1 全部 API 端点(详情页内联 JS 10,078 字符完整逆向)

| 端点 | 方法/参数 | 响应分支 |
|------|----------|---------|
| `/ShoppingCart/Add` | POST {fileId, code} | 返回购物车数量字符串 |
| `/HFBSAPI/IsUserSessionValid` | GET | {state, sessionValid} |
| `/HFBSAPI/Login` | GET {username, password} | SUCCESS / INVALID_CREDENTIALS |
| `/HFBSAPI/Register` | GET {gToken, username, email, password, firstname, lastname, phone} | SUCCESS / EXIST(查重) |
| `/HFBSAPI/ProcessEditableStandardComponent` | GET {code} | 把标准组件复制进 HFBS |
| `/HFBSAPI/GetRequestToken` | GET | {state, url} → window.open 一次性跳转 HFBS |
| `/StandardComponents/ShareItemViaEmail` | POST {name, email} | 成功后关模态 |

### 12.2 实测验证(接口级)

- POST /ShoppingCart/Add 实测:**返回 "1"**,与 JS `$(".cart-badge").html(data)` 严格对应
- **同 fileId 重复加购仍返回 1 → 购物车按文件去重**(业务规则)
- 会话机制实证:`Set-Cookie: ASP.NET_SessionId=...; HttpOnly; SameSite=Lax` —— 匿名购物车 = 服务端 Session,关浏览器即失效,无持久化
- "more" 展开逻辑:`removeClass("mask") + hide()`(CSS 遮罩渐隐,非截断)

### 12.3 表单验证规则(实证)

- 登录:username/password required(无验证码)
- 注册:7 字段 required + password minlength 6 + **reCAPTCHA v2**(verifyCallback→gToken,未通过则注册按钮 disabled)
- 分享:email required + 格式校验

### 12.4 交互↔业务对应验证结论

| 链路 | 对应状态 |
|------|---------|
| 列表→详情(607 行 ↔ 607 页) | ✅ 100% 抓取成功率交叉验证 |
| 详情→PDF(ViewPDF) | ✅ 实测下载 749KB 真 PDF |
| 详情→加购→badge | ✅ 实测返回值与 UI 更新逻辑吻合 |
| 详情→HFBS 编辑(登录/注册/复制/跳转) | ✅ JS 全文 + 4 个 API 实证 |
| 分册链接(10/10)、FPU(63↔70 关系) | ✅ 全量抓取验证 |
| **结算→PayPal→Revit 下载** | ❌ 需真实账号+付款,无法匿名实证 |
| **HFBS SaaS 内部** | ❌ 一次性 token 跳转后,域外 |

### 12.5 安全观察(复刻版必须改进)

1. **密码走 GET query 传输**(会进服务器/代理日志)——复刻版必须 POST + 哈希传输
2. 登录无验证码(注册有)——防爆破薄弱
3. 购物车纯 Session 无持久化——复刻版建议 cookie/DB 持久化
