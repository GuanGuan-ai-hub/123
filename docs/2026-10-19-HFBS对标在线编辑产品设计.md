# 医疗工艺在线编辑平台产品设计(HFBS 对标)

> 定位:中文版从"只读组件库"升级为"可编辑的医疗工艺数据平台"
> 对标:TAHPI HFBS(Health Facility Briefing System,hfbsinfo.com)
> 依据:iHFG 逆向报告 + 607 组件数据模型
> 日期:2026-10-19

---

## 1. 对标分析:HFBS 在做什么

从逆向证据看,iHFG 与 HFBS 的关系:

| 证据 | 解读 |
|------|------|
| 组件详情页有 "Edit it in Health Facility Briefing System (HFBS) / Edit Briefing" 按钮 | 组件库(内容)与编辑器(工具)分离,SaaS 是变现核心 |
| iHFG 的登录/注册模态与 HFBS 共用体系 | 一个账号双产品,免费看 + 付费改 |
| 详情页 RDS 元素带全局 ID(装修项 3092、设备 8309 等) | HFBS 数据库是"主数据",iHFG 网页只是其只读投影 |
| RLS PDF 免费 / Revit 文件 $64.99 / HFBS 订阅 | 三级变现:看→用→改 |
| HFBS Logo 出现在 iHFG 每个页面 | 双向导流 |

**HFBS 本质**:把医院设计任务书(Briefing)从 Excel/Word 搬到云端数据库,以标准组件为原子单元,按项目组织,支持编辑、复用、导出。

## 2. 目标用户与场景

| 角色 | 场景 | 痛点 |
|------|------|------|
| 医院建设方/筹建办 | 立项阶段编制医疗工艺方案 | 无标准库,靠咨询公司,周期长费用高 |
| 医疗工艺咨询师 | 多项目并行编制任务书 | Excel 版本混乱、复用难、无协同 |
| 建筑设计师 | 拿到房间清单做平面设计 | 房间数据与图纸脱节,Revit 无结构化数据源 |
| 院方使用科室 | 提需求、确认房间配置 | 看不懂工程文档,参与门槛高 |

**核心场景一句话**:项目经理创建项目 → 按科室(FPU)组织 → 从 607 个标准组件选型入项目 → 在线改参数(面积/设备/装修) → 团队协作与院方确认 → 导出任务书清单与 Revit 数据。

## 3. 产品定位与差异化

- **定位**:面向中国医疗建设市场的"医疗工艺数据中台"——标准组件库 + 项目化在线编辑 + 数据交付
- **差异化**:
  1. 本土规范对齐(GB 51039《综合医院建筑设计规范》、各地建设标准)替代 iHFG 的澳洲体系
  2. 中文 + 本土化计价(订阅 ¥ 而非 $)
  3. 面向 Revit 国产替代生态(广联达/品茗等)的数据导出,不只 Revit
  4. 演示站已有的免费组件库即获客漏斗(对标 iHFG→HFBS 导流)

## 4. 功能架构

```
医疗工艺数据平台
├── 标准组件库(已有演示站,只读)
│   ├── 组件浏览/搜索/对比
│   └── FPU / 指南分册关联
├── 项目工作台(新增核心)
│   ├── 项目管理:新建/归档/成员与角色(管理员/编辑者/查看者)
│   ├── 科室树:按 FPU 模板初始化科室与房间清单
│   ├── 组件实例化:从标准组件"引用"生成项目实例
│   └── 版本与修订:每次修改留痕(对标 RDS 的 Amendment 字段)
├── 在线编辑器(新增核心)
│   ├── RDS 三表编辑:头部元数据 / 装修构造表 / 设备家具表
│   ├── 行级操作:增删改设备行、调数量、换材料(带全局物料字典)
│   ├── 偏离标记:相对标准版的差异高亮(面积/设备增减)
│   └── 布局图关联:RLS 占位图 + CAD/Revit 文件挂接
├── 协同与确认流
│   ├── 评论与 @ 提及(房间级/字段级)
│   ├── 院方确认链:生成只读确认页,微信分享 + 确认记录
│   └── 变更通知:组件参数变更推送到引用项目
├── 交付导出
│   ├── 任务书 PDF(项目级/科室级)
│   ├── 房间清单 Excel(面积汇总表)
│   ├── Revit/广联达数据包(房间+编码+参数 JSON/CSV)
│   └── 标准组件市场:付费 Revit 布局图(对标 $64.99 单品)
└── 账号与计费
    ├── 免费版:浏览 + 1 个项目 ≤ 20 房间
    ├── 专业版(订阅):多项目、协作、导出
    └── 企业版:私有部署、自有组件库定制
```

## 5. 数据模型(基于逆向模型扩展)

标准库(平台维护)与项目实例(用户编辑)分离,引用 + 偏离:

```
StandardComponent (607,已逆向)
  ├─ code/name/slug(索引,已有)
  ├─ RdsHeader: 面积/运营时间/占用/描述/修订史(已有数据)
  ├─ Finish[]: 装修构造行(已有 5,505 行)
  ├─ Equipment[]: 设备家具行(已有 7,128 行)
  └─ File: RLS-PDF / Revit(付费)

Project(新增)
  ├─ 基本信息: 名称/医院/阶段(可研/初设/施工图)
  ├─ Member[]: 用户+角色
  └─ Department[](科室,从 FPU 模板实例化)
       └─ RoomInstance[](房间实例)
            ├─ sourceComponentId → StandardComponent(引用)
            ├─ overrides: { area?, name?, … } JSON 偏离字段
            ├─ customFinishes[] / customEquipment[](增删的行)
            ├─ comments[](字段级评论)
            └─ status: draft / reviewing / confirmed
MaterialDict(全局物料与设备字典,复用逆向数据中的全局 ID)
```

要点:**实例不复制标准件,只存偏离(diff)**——标准库升级时项目可感知变更,这是 HFBS 数据库式管理的关键,也是相对 Excel 方案的本质优势。

## 6. 关键页面与交互流

1. **项目总览**:科室树 + 房间计数 + 面积合计 + 进度(草稿/待确认/已确认)
2. **科室页**:FPU 模板一键初始化(勾选 FPU → 自动带入推荐房间组合),房间列表支持从标准库追加
3. **房间编辑页**(核心):三段式,头部表单 + 两张可编辑表格;每行有"标准值/已修改"双态;右侧栏显示修订历史与评论
4. **偏离对比页**:某房间 vs 标准组件的并排 diff(对标 HFBS 的 Briefing 修正流)
5. **确认流**:生成只读链接 → 院方在微信内打开 → 逐房间点"确认" → 留存确认人与时间
6. **导出中心**:按项目/科室/房间三级导出 PDF、Excel、BIM 数据包

## 7. 技术方案(现有演示站的演进路径)

| 层 | 现演示站 | SaaS 版建议 |
|----|---------|------------|
| 前端 | Next.js 静态导出 | Next.js(App Router)+ RSC,编辑器页客户端组件 |
| 数据 | 本地 JSON | PostgreSQL + Prisma/Drizzle;标准库表 + 项目表分离 |
| 认证 | 无 | Auth.js(微信扫码 + 账号密码) |
| 权限 | 无 | RBAC(项目成员角色),行级由 roomInstance 归属控制 |
| 协同 | 无 | MVP 用乐观锁(更新时间戳)避免并发覆盖;实时协作后迭代(CRDT/Yjs) |
| 导出 | 无 | PDF:服务端渲染模板;Excel:exceljs;BIM 包:JSON/CSV |
| 部署 | 静态托管 | Vercel/国内云(需备案)+ 托管 PG(Neon/RDS) |

MVP 技术要点:房间编辑器是复杂表单,建议 TanStack Form + Zod 校验;偏离 diff 用 JSON Patch(RFC 6902)存储,天然支持版本回放。

## 8. MVP 与迭代路线

- **M1 最小可用**:项目/科室/房间三级 + 从标准库选型 + RDS 三表在线编辑 + 导出任务书 PDF。验证"数据结构化编辑"价值
- **M2 协作**:成员/角色 + 评论 + 确认流(微信分享)。验证院方参与场景
- **M3 交付深化**:Excel/BIM 导出 + 面积汇总统计 + 偏离对比页。覆盖设计院交付
- **M4 商业化**:订阅计费 + 付费 Revit/布局图市场 + 自有组件库(企业版)

## 9. 商业模式(对标 HFBS 三级变现)

1. **免费**:全站浏览标准库(获客)
2. **订阅**:专业版按席位/年,对标 HFBS 订阅
3. **单品**:布局图/BIM 数据包按件计价(对标 $64.99 Revit 件)
4. **企业**:私有化 + 定制标准库(政府/集团医院)

## 10. 风险与合规

- **内容版权**:标准库初始内容必须自建(对接 GB 51039 等),已逆向的 607 组件数据仅作内部格式参考,不得直接上线(演示站 README 已标注)
- **数据合规**:医院项目信息敏感,需数据加密、权限审计日志;私有部署是企业版诉求
- **竞品**:国内已有医疗工艺咨询公司自研工具,差异化在"标准库开放 + 轻量订阅 + 数据交付"
